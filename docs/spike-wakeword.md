# Спайк wake word (спринт 0, ТЗ §17, §5.1)

**Статус: решение принято, реальный замер НЕ выполнен.**
Скрипт замера готов (spike/wake_spike.py), запущен только в синтетическом режиме.
Причина: на машине разработки нет ни микрофона, ни модели vosk-model-small-ru,
ни пакетов pvporcupine / openwakeword. Синтетические тон и тишина ничего не
говорят о качестве детекции, поэтому числа задержки и ложных срабатываний в
этом отчёте отсутствуют. Их надо получить на целевой машине владельца и
вписать в таблицу в конце.

## Что нужно было получить

ТЗ требует: «есть движок, порог, задержка, уровень ложных срабатываний;
проверены Porcupine / openWakeWord / Vosk KWS».

Метрики скрипта:

| Метрика | Как считается | Целевое значение |
|---|---|---|
| Задержка | кадры от первого кадра записи до срабатывания × 32 мс | заметно меньше 300 мс |
| Ложные срабатывания на тишине | срабатывания на записях без речи | 0 |
| Ложные срабатывания на речи | срабатывания на обычных фразах без слова VoiceRunaCore | 0 |
| Пропуски | не сработавшие записи со словом VoiceRunaCore | 0 из 10 |

## Методология

1. Записать материал: 3–5 файлов тишины/фонового шума, 5–10 файлов обычной речи
   без кодового слова, 10 файлов с VoiceRunaCore в начале. 16 кГц, моно, WAV.
   Имена файлов задают класс: wake-*.wav, silence-*.wav, speech-*.wav.
2. Положить в spike/samples (папка в .gitignore, записи не коммитим).
3. Прогнать все движки:

```
python spike/wake_spike.py --mode wav --wav spike/samples --engine all
```

4. Для каждого движка подобрать порог так, чтобы ложных срабатываний на
   тишине и обычной речи было 0, и зафиксировать его как wakeword.threshold.
5. Проверить, что при wakeword.bargein_bump = +0.15 слово VoiceRunaCore поверх
   играющего ответа всё ещё срабатывает (barge-in, §2.6).

Режим --mode mic записывает с микрофона по кругу («молчите», затем «скажите
VoiceRunaCore») — быстрый способ проверить сам факт срабатывания.
Режим --mode synth запускает скрипт без звука и нужен только для проверки,
что код движка и вывод таблицы работают: на синтетическом тоне детектор
обязан молчать, это не измерение качества.

## Сравнение движков

| Движок | Офлайн | Русский | Зависимости | Интеграция |
|---|---|---|---|---|
| Vosk KWS | да | да, модель small-ru (~45 МБ) | пакет vosk, уже в requirements | грамматика из wakeword.phrase, распознаёт «вокс/вокса/воксу» |
| Porcupine | да | только со своим .ppn-словом | pvporcupine + ключ Picovoice | нужен платный/бесплатный ключ и собственное слово, которого у нас нет |
| openWakeWord | да | нет готового слова «вокс» | openwakeword + обученная модель | нужна обученная модель под своё слово |
| none | — | — | — | только хоткей Ctrl+Alt+V |

## Решение

1. **wakeword.engine = vosk** по умолчанию. Он единственный, который даёт
   офлайн-детекцию русского слова без отдельного обучения модели и без ключа
   стороннего сервиса; модель весит ~45 МБ и уже описана в конфиге.
2. **Fallback — только хоткей.** Если пакет vosk не установлен или модели нет
   в models/, create_wake_detector() возвращает движок none: ассистент
   полностью работоспособен, активация — Ctrl+Alt+V и POST /listen.
   Это соответствует ТЗ §5.1 («если wake word не взлетел — остаётся только
   хоткей; проект от этого не блокируется»).
3. **Порог 0.5, barge-in +0.15** как стартовые значения; после замера
   подставляются полученные. Порог живёт в конфиге и правится без перезапуска.
4. Porcupine и openWakeWord оставлены как подключаемые бэкенды (классы
   PorcupineBackend и OpenWakeWordBackend): они включаются конфигом, если
   владелец достанет ключ/модель, но в дефолт не попадают.

## Почему не выбрали Porcupine / openWakeWord сейчас

- Porcupine требует PORCUPINE_ACCESS_KEY и собственное слово: встроенного
  «вокс» нет, а генерация .ppn — отдельный шаг с ключом.
- openWakeWord: готовых русских моделей под «вокс» нет, обучение своего слова —
  отдельная задача вне спринта 0.
- Vosk KWS уже покрывает требование «офлайн + русский + падежи», а модель
  скачивается нашим ModelDownloader с прогрессом.

## Что осталось сделать (на целевой машине)

```
# 1. скачать модели: в приложении это делает ModelDownloader (с прогрессом в окне),
#    вручную — из sidecar/:
cd sidecar
python -c "import asyncio; from voiceruna.config import ConfigManager; from voiceruna.events import Event; from voiceruna.voice.download import ModelDownloader; c = ConfigManager(); c.load(); d = ModelDownloader(c, lambda e: print(e.to_json())); asyncio.run(d.ensure_models('all')); asyncio.run(d.aclose())"
# 2. записать материал в spike/samples и прогнать
python spike/wake_spike.py --mode wav --wav spike/samples --engine all
```

Таблица для заполнения:

| Движок | Порог | Задержка, медиана | Ложные на тишине | Ложные на речи | Пропуски |
|---|---|---|---|---|---|
| vosk | 0.50 | — не измерено | — | — | — |
| porcupine | — | недоступен без ключа | — | — | — |
| openwakeword | — | недоступен без модели | — | — | — |

## Риски

- Vosk KWS на «вокс» может путать слово с «бокс/вокзал»; при замере смотреть
  именно ложные срабатывания на речи, при необходимости поднять порог.
- Задержка Vosk выше, чем у Porcupine (буферизация распознавателя); если
  медиана выйдет за 300 мс, увеличивать нечего — это аргумент в пользу
  Porcupine при наличии ключа.
- Модель small-ru (~45 МБ) добавляется к первому запуску; прогресс уже есть,
  но общий вес установщика вырастет.
